# 人脸签到系统 · 手机界面方向稿

设计依据为 week1 分支的 `3b7b928`。项目用同一部手机服务两类操作：任何人都可以拍照打卡，登录者可以管理自己的标准照并查询考勤。首次使用的学生需要先注册并录入标准照。三个方向都以 375 × 812 的访客首页作比较，另查 1440 × 900 的桌面布局。[简要设计](../week1/人脸签到系统简要设计.md) · [REST API](../week1/REST-API.md)

## 共同的交互约定

| 场景 | 正式 Vue 3 前端须遵守的约定 |
| --- | --- |
| 访客首页 | 首页直接打开现场拍照。已登录其他账号也可供下一人打卡。公开结果只显示返回的脱敏姓名、服务器时间和当日状态。 |
| 注册 | 姓名去首尾空白，学号保留前导零，密码保留原始输入。拍照、相册二选一，预览后随账号字段一并提交。注册成功进入登录页。 |
| 账号 | 同源会话 Cookie。刷新时恢复账号，过期时引导登录，退出后清理个人信息。 |
| 照片库 | 本人从会话取用户 ID。管理员可按完整学号分页查找。支持查看、替换、删除和补录；更换失败保留旧照，删除后保留历史考勤。 |
| 打卡 | 每次新拍摄对应一个 UUID，同一照片重试复用原编号。过载或处理中读取 Retry-After。歧义、拒识、无人脸、多人脸和服务不可用分别反馈。 |
| 考勤 | 显示服务器按北京时间汇总的结果，首条待签退，两条起显示最早和最晚时间。个人仅按日期查询，管理员还可以按学号筛选。 |

第 2 周真机联调优先贯通注册、标准照上传、登录、查看照片和退出。三份 HTML 供选型，允许在浏览器检查入口和选图流程；生产请求、会话和权限由选定方向的 Vue 3 实现承接。

## 三个初稿

| 方向 | 设计思路 | 现场操作与视觉主体 |
| --- | --- | --- |
| A 取景打卡 | 从 Dieter Rams 的设备操作思路出发，将启动动作和取景位置放在一起。 | 光圈几何和快门构成首页中心；深绿背景上只强调当前可执行的动作。适合已录入的学生轮流使用同一部手机。 |
| B 校园签到台 | 用田中一光的公共导视思路组织三项任务，每一条入口都能单独辨认。 | 校园窗格与日光构成几何图形，群青横向入口和留白区分打卡、首次注册和账号访问。适合首次使用和课程演示。 |
| C 考勤日历 | 轮盘秒数 22，东亚样张第 11 号。借佐藤可士和式单一符号锚点，用日号承载这个产品的时间语义。 | 以北京时间当天日号和所在周定位打卡日期；突出一个日号，给操作区留出连续空间。周历仅作日期定位。 |

## 其余三个候选

- **任务清单**。借公共服务网站用一行表示一项任务的组织方式，以「注册录入」「拍照打卡」「查看记录」作为入口。同一设备上的下一位使用者可能误读完成标记，因此仅作为备选。[GOV.UK 任务清单](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)
- **分步录入**。借过程列表的有序阅读方式，先填账号再检查标准照。适合展开注册页，在首页会给每天来打卡的学生增加阅读量。[USWDS 过程列表](https://designsystem.digital.gov/components/process-list/)
- **校园拼贴**。轮盘秒数 22，网页样张第 3 号。让独立色块对应快门、照片或账号动作，以大小表现使用频率，视觉密度比入选方案高。
