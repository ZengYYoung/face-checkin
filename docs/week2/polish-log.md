# 方向稿浏览器复核

使用本机 Chrome 和 Node Playwright 在 375 × 812、1440 × 900 两种尺寸渲染。每个尺寸的整页和首屏等高。逐版点击首页入口，以测试 PNG 检查现场拍摄入口、相册选择、图片预览及可编辑的登录表单。三版均通过，未观察到页面脚本异常或水平溢出。截图和 HTML 均位于 [design-demos](./design-demos/)。

| 方向 | 看图和操作后所作调整 |
| --- | --- |
| 取景打卡 | 原说明在窄屏把「标准照」拆开，且读完第二句才知道谁可直接打卡。将免登录条件放在第一行，拍摄要求独立成行。 |
| 校园签到台 | 首页顶栏和服务列表都有登录入口。首页保留带操作说明的列表入口；首屏补明免登录条件。点注册时发现图标与注册页共用锚点，拆开命名并验证可打开注册表单。 |
| 考勤日历 | 初稿点击主按钮后还需再点一次才调起相机。改为一次点击打开相机输入，取消后可在面板中重新拍摄。日期旁的说明补明首次打卡的业务含义。 |

这里验证的是浏览器文件选择事件和本机预览。HTTPS 下调起手机原生相机、会话 Cookie、接口错误、服务端考勤汇总和 FRS 识别需要在正式实现后联调。

## C 方向正式版

第一轮按选定稿删除首页说明，检查 375 × 812 和 1440 × 900 的日历、标题与拍照按钮间距。第二轮检查标准照、日期筛选、分页和结果反馈，缩短图片格式提示并保持大小单位同排，合并考勤行重复显示的「待签退」。

本机 Chrome 使用拦截的测试响应验证了全部十项 API 操作，包括注册保留学号前导零及密码空格、刷新恢复会话、学生权限、管理员精确查询、标准照读取与增删改、换照失败保留旧照、考勤范围和分页、退出及过期。匿名打卡覆盖相同照片和 UUID 在 429、处理中与成功重放之间保持一致，重新拍摄生成新 UUID，歧义与拒识分别反馈。测试验证前端请求与渲染，服务器写入及 FRS 识别仍需在真实环境验收。
